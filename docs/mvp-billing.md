# ThePayOne billing and usage

## 상품과 권한

- 이지컷 프로: 월 9,900원 자동결제, 승인마다 기본 처리시간 60분 지급, 프로젝트 30일 보관
- 스타터 패키지: 3·6·12개월 단건 결제, 활성 기간 중 매월 200분 지급
- 전문가 패키지: 3·6·12개월 단건 결제, 활성 기간 중 매월 600분 지급
- 기간 패키지는 자동결제 일정을 만들지 않으며 스타터·전문가의 3·6·12개월 각 상품은 계정당 한 번만 구매할 수 있다.
- 서로 다른 기간 또는 등급의 패키지는 각각 한 번씩 추가 구매할 수 있다.
- 복수 패키지는 각각 독립된 이용기간과 월별 지급일을 가지며, 지급된 시간은 합산한다.
- 신규 기간 패키지는 독립된 월별 이용권 3·6·12개를 선결제하는 환불정책 v2 주문이다. 계약 월단가는 실 결제금액을 계약 개월 수로 나누며, 종료된 월과 현재 사용한 월은 월단가로 공제하고 현재 미사용 월과 미래 월을 환불한다.
- 현재 월을 공제한 환불은 그 월 종료일까지 권한과 남은 기본시간을 유지하고 미래 월 지급을 중단한다. 현재 월이 완전히 미사용이면 환불 완료 시 즉시 종료한다. 추가시간만 사용한 작업은 패키지 사용 월로 중복 계산하지 않는다.
- 기존 주문은 `billing_orders.refund_policy_version = 1`을 유지해 경과일수·위약금 방식으로 계산하고, 신규 주문은 기본값 `2`를 기록해 월별 방식으로 계산한다.
- 얼리버드 추가시간은 300·600·1,000분 단건 상품이며 승인일부터 90일간 유효하다.
- 모든 카드 승인은 현재 일시불만 허용한다.
- 결제 이력이 없는 비유료 회원은 로그인 완료 시 온보딩 여부와 무관하게 원본 영상 처리시간 20분을 계정당 한 번 받고, 30일 동안 쇼츠 생성에 사용할 수 있다. 관리자 `운영 설정` 탭에서 신규 지급을 즉시 ON/OFF할 수 있고, `ONBOARDING_WELCOME_GRANT_ENABLED=false`는 배포 환경의 긴급 강제 중지로 남긴다. 체험 프로젝트는 동시 작업 1개·1일 보관·수정 반영 1회로 제한한다.
- 사용량 원장은 결제 주문이 연결된 `paid`와 무료 체험·이벤트·피드백·운영자 지급인 `complimentary`를 분리한다. 결제 후 작업은 유료 사용량을 먼저 예약하고 유료 잔액이 부족할 때만 무료·보너스 사용량을 이어서 사용한다.

`user_subscriptions`와 `usage_grants`만 유료 권한을 부여합니다. `app_users`와 `mvp_sessions`의 `selected_plan_code`는 호환성 캐시입니다.
로그인 체험시간은 결제 권한이 아니라 별도 `usage_grants.product_code`로 식별하며 실시간 인기 필터, 커스텀 템플릿, 전자책 등 유료 전용 권한을 부여하지 않습니다.

## 결제 흐름

- 최초 결제 1단계: 카드·휴대전화 정보를 받아 `/api/auth`에 `udf2=00`으로 0원 확인용 임시 `cardId` 발급
- 최초 결제 2단계: 결제자 이름·이메일 확인 → 임시 `cardId` 폐기 → 실제 상품 조건으로 최종 `cardId` 재발급 → 최종 `cardId`로 `/api/pay` 즉시 승인
- 이지컷 프로 첫 결제: 월 9,900원 승인 → Pro 이용기간 1개월과 기본시간 60분 생성 → 더페이원 월간 일정 활성화
- 이지컷 프로 자동갱신: 더페이원 자동 승인 → 결과 통지 검증 → 기본시간 60분 지급 → 기존 Pro 이용기간 끝에 1개월 추가
- 이지컷 프로 해지: 확인 오버레이에서 최종 해지한 즉시 더페이원 일정을 `중지`; 이미 결제한 Pro 기간과 지급시간은 유지하지만 다음 결제·지급은 중단
- 이지컷 프로 다시 구독: 저장 카드의 생년월일/사업자번호와 카드 비밀번호 앞 2자리 확인 → 9,900원 즉시 승인 → 60분 지급 → 기존 Pro 이용기간 끝에 1개월 추가 → 일정 `사용`
- 이지컷 프로 → 기간 패키지: 현재 Pro 이용기간 종료일로 변경 예약하고, 종료 뒤 패키지 단건 결제를 완료해야 적용
- 카드 변경: 새 일정을 등록하고 기존 더페이원 일정을 `중지`; 미납 상태면 현재 플랜 금액 즉시 승인
- 기간 패키지: 최종 등록한 `cardId`로 `/api/pay` 일시불 단건 승인하며 자동결제 일정은 만들지 않음
- 기간 패키지 지급: 첫 월 지급량은 승인 즉시 생성하고, 활성 상태인 동안 `next_quota_at`마다 월 지급량을 추가; 종료·만료 뒤에는 지급하지 않음
- 애드온: 저장된 `cardId`와 연락처를 재사용해 서버 승인하고, 서버 응답 또는 검증된 결과 통지 중 먼저 완료된 경로가 멱등하게 grant 생성

카드번호·유효기간·생년월일·사업자번호·카드 비밀번호는 결제 요청에만 사용하며 DB, 브라우저 저장소, 애플리케이션 로그에 남기지 않습니다. `cardId`는 레코드 ID를 AAD로 쓰는 AES-256-GCM 암호화본과 조회용 SHA-256 해시만 저장합니다. 최초 결제 연락처는 별도 AAD 문맥의 AES-256-GCM 암호화본으로 결제수단에 저장하며 플랜 변경·갱신·추가시간 결제에서 복호화해 재사용합니다.

모든 카드 승인 요청은 `Installment=00`으로 고정합니다. 클라이언트가 0이 아닌 할부개월을 보내면 서버에서 거절하며, 승인 응답이나 결과 통지의 할부개월이 주문 스냅샷과 다르면 자동 확정하지 않습니다. 가격 페이지의 2단계 결제창은 1단계에서 더페이원 0원 카드 인증을 수행하고, 암호화한 임시 `cardId`를 15분 동안만 보관합니다. 2단계 결제 시 임시 ID를 먼저 폐기한 뒤 최종 `cardId`를 새로 발급해 그 ID로 결제합니다. 결제하지 않은 임시 등록은 카드 정보 변경·결제창 이탈 또는 만료 정리 작업에서 폐기합니다.

## 결과 통지 보안

- 경로: `${THEPAYONE_WEBHOOK_BASE_URL}/api/webhooks/thepayone/${THEPAYONE_WEBHOOK_SECRET}`
- Vercel Firewall에서 해당 경로는 더페이원 공식 IP `203.245.13.111`만 허용
- 앱은 `mchtId`, `tmnId`, `trackId`, `cardId` 해시, 거래 유형, 금액을 DB 주문과 대조
- `(provider, trxId)` 고유 제약으로 중복 통지와 중복 권한 지급 차단
- 관리자 환불 통지는 환불 원장과 대조하고, 불일치·외부 취소·알 수 없는 이벤트는 `manual_review`로 보류
- 수동 업그레이드 부분환불 통지는 원거래번호와 금액이 정확히 일치할 때만 원장을 멱등하게 `completed`로 전환
- HMAC 헤더가 제공되면 IP 제한과 함께 서명 검증을 추가

통지 본문은 `application/x-www-form-urlencoded`의 `response=` 중첩 쿼리 형식입니다. 정상 수신 또는 안전하게 보류한 이벤트에는 `result=0000`을 반환해 불필요한 재전송을 막습니다.

## Cron과 실패 처리

시간별 `/api/cron/billing-renewals`는 결제를 직접 승인하지 않습니다.

1. 활성 기간 패키지의 월별 base grant 생성
2. 만료된 checkout과 임시 카드 인증 정리
3. 월간 결제일 후 기본 6시간 내 통지가 없으면 `past_due` 전환
4. 해지·상품 변경·기간 패키지 만료 시 권한 종료 및 카드 일정 중지

민감 인증값을 저장하지 않으므로 실패 결제를 서버에서 임의 재시도하지 않습니다. 사용자는 확인 오버레이에서 카드 인증값을 다시 입력하거나 결제수단을 변경해 복구합니다.

## 운영 설정

필수 환경변수는 `.env.example`의 `THEPAYONE_*`, `DATABASE_URL`, `CRON_SECRET`입니다. `THEPAYONE_BILLING_ENABLED=false` 상태에서 먼저 DB 마이그레이션, 통지 URL 등록, Vercel Firewall 규칙, 실제 소액 승인·취소를 검증한 뒤 운영에서만 `true`로 전환합니다.

더페이원에는 별도 테스트 서버가 없으므로 `/api/pay` 성공은 실제 승인입니다. 로컬 3분/5회 테스트는 [더페이원 로컬 정기결제 테스트](thepayone-local-card-test.md)를 따릅니다.

운영에서는 `MVP_PLAN_ENFORCEMENT=true`를 유지합니다. 작업 제출 시 원본 길이를 분 단위로 예약하며 남은 초가 30초 이하면 버리고 31초 이상이면 다음 분으로 올립니다(최소 1분). 렌더 성공률 50% 이상이면 최종 차감하며 50% 미만 또는 시스템 실패면 예약량을 복구합니다.

로그인 체험 지급과 소비는 서비스 역할에서만 실행합니다. 로그인 완료 뒤 단일 SQL 문이 DB의 `login_welcome_grant` 런타임 플래그를 확인한 다음 지급과 안내 이력을 함께 생성하고, `(user_id,product_code)` 부분 고유 인덱스로 재로그인·동시 로그인에 의한 중복 지급을 차단합니다. 관리자 토글을 OFF로 바꿔도 기존 지급분은 회수하지 않으며 이후 로그인 신규 지급만 막습니다. 체험 계정은 체험 grant만 예약할 수 있으며 결제·이벤트·피드백 grant를 합쳐 우회할 수 없습니다. 기존 계정별 YouTube 분석 속도 제한과 작업 동시성 제한도 동일하게 적용합니다.
활성 유료 권한이 생기면 결제 주문이 연결된 grant를 무료·보너스 grant보다 먼저 예약합니다. 환불의 사용 여부는 해당 결제 주문의 `paid` grant 예약·소진 이력만으로 판정하므로, 결제 전 무료 체험 사용은 유료 주문 사용으로 오인하지 않고 결제 후 첫 작업은 유료 주문 사용으로 남습니다.

## 관리자 결제 화면

- `/admin/easycutcutcutcutcutcut`은 검색 노출을 차단한 관리자 전용 경로다. 경로 자체는 인증 수단이 아니며 페이지와 환불 API가 모두 `app_users.is_admin`을 서버에서 확인한다.
- 결제 주문, 총매출·환불·순매출, 활성·연체 구독, 수동 확인 대상을 조회할 수 있다.
- 더페이원 환불은 별도 관리자 환불 원장과 감사 로그에 기록하며 `request_id`로 중복 실행을 막는다.
- 미사용 추가 상품의 전액 환불은 이용권을 자동 회수한다. 구독 환불은 자동결제 일정과 잔여 권한을 관리자가 대조하도록 `manual_review`로 남긴다.
- 실시간 인기의 기본 목록·잠긴 필터 클릭은 사용으로 보지 않는다. 활성 이용권 전용 필터 결과를 서버가 정상 반환한 첫 페이지 요청만 결제 주문에 연결해 기록하며, 이력이 있으면 `7일 이내 미사용 청약철회` 유형의 자동 전액환불을 차단한다.
- 환불정책 v2 기간 패키지는 관리자 환불 요청 시 완료 월수와 현재 월 사용 여부를 서버에서 다시 계산한다. 현재 사용 월을 공제하면 환불 원장의 권한 조치를 `scheduled_end`로 기록하고 월말에 종료되도록 구독 종료일·기본시간 만료일을 단축한다. 현재 미사용 월까지 환불하면 즉시 권한과 기본시간을 회수한다.
- `할부 혜택` 탭의 기존 캠페인 자료는 관리용으로 유지하지만 고객 결제창에는 할부 선택을 제공하지 않는다.
- Nicepay 과거 거래는 조회만 제공하며 자동 환불하지 않는다.
- `운영 설정` 탭의 `무료 사용량 지급` 토글은 매 변경 시 확인 오버레이를 거치며, 변경 전·후 값과 관리자를 감사 로그에 기록한다.
