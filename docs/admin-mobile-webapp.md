# EasyCut 개인 관리자 웹앱

주소: `/admin-app/index.html`. 기존 EasyCut 관리자 계정으로 로그인한다. iPhone은 Safari에서 홈 화면에 추가한 뒤 설정 → 푸시알림 켜기를 누른다. 기기 권한은 사용자가 한 번 허용해야 한다. 같은 설정 화면에서 테스트 알림, 기기 연결 해제, 결제/운영 알림, 야간 긴급 알림, 금액 표시를 조정한다.

## 구성

- 독립적인 HTML/CSS/JavaScript PWA. 기존 서비스의 UI와 별도로 관리하며 기존 관리자 인증을 공유한다.
- 오늘, 운영, 매출, 알림의 네 화면. 서울 시간, 통화별 승인액, 선택 기간 승인 결제의 누적 환불액, 최근 결제 100건을 조회한다. Paddle sandbox는 제외한다.
- API는 관리자 쿠키 검사, 변경 요청의 동일 출처 검사, private/no-store를 적용한다. 브라우저에 운영 데이터는 저장하지 않는다. 미리보기는 `?preview=1`에서만 명시적 가상 데이터를 사용한다.
- Service Worker는 관리자 앱 범위에서만 작동하고 오프라인 안내 페이지만 저장한다. 최신 화면은 실행할 때 네트워크에서 받는다. 앱 재설치는 필요 없다.
- 기존 Vercel의 `/api/cron/admin-mobile`이 매분 승인된 결제와 운영 상태를 확인한다. 현재 등록 시점 이후의 결제만 알림으로 만든다. 새 고정비 서비스는 없다.
- 결제, 수집 보호 회로, 제작 대기 정체, 여러 고객의 제작 실패, 수동 검토 결제를 알림함에 기록한다. 조건 해소는 연속 2분 확인 뒤 복구 알림을 만든다. 처리나 환불을 자동 실행하지 않는다.
- 구독별 전송 이력·잠금·최대 3회 재시도를 사용한다. 프로바이더 수락 직후 서버 중단 시 재전송 가능성은 남지만 동일 사건의 notification tag를 사용한다. 만료된 기기는 비활성화한다.
- 23–08시 KST 일반 알림은 푸시를 생략하고 알림함에 보존한다. 긴급도 운영 알림을 끈 사용자의 기기에는 발송하지 않는다.

## 서버 설정

`ADMIN_MOBILE_ENABLED=1`, `ADMIN_PUSH_VAPID_PUBLIC_KEY`, `ADMIN_PUSH_VAPID_PRIVATE_KEY`, `ADMIN_PUSH_VAPID_SUBJECT`, 기존 `CRON_SECRET`와 `DATABASE_URL`. private key는 서버에서만 사용하며 교체하면 기존 기기 재연결이 필요하다.

추가 스키마는 `202610050001_admin_mobile_push.sql` 하나다. shorts_mvp의 관리자 전용 6개 테이블만 생성하고 RLS를 적용한다. public/anon/authenticated의 직접 접근은 차단한다. 기존 결제·작업 테이블을 수정하지 않는다.

## 확인 범위와 데이터 한계

- 현재 운영 기준 커밋: `03a0e876da6a8a3b13bc3d11b26f4c8bf588ea3b`. 전용 브랜치 `codex/admin-pwa-20261005`.
- `ADMIN_IP_INVENTORY_FUNCTION_ARN`의 관리자 전용 읽기 함수가 실제 최근 72시간 YouTube 워커의 정확한 revision과 IP 설정 참조를 확인한다. 허용된 설정의 버전 이력으로 현재 IP 익명 식별자와 확인 시작 시각을 계산한다. 원문 IP/프록시 인증/다른 비밀값은 웹으로 반환하거나 로그에 기록하지 않는다. `ADMIN_ROUTE_ASSIGNMENTS_JSON` 수동 설정은 사용하지 않는다.
- 1/6/24/72시간 구간은 IP의 확인된 이력 이후로 자른다. 교체 전 만들어진 작업의 뒤늦은 보고도 제외한다. 이력이 잘렸으면 정확한 교체일 대신 확인 시작이라고 표시한다. stage rollback, 새 미허용 설정 참조, 서로 다른 현재 IP, 조회 오류는 미확인으로 처리한다. lease/release updated_at과 quality_reset_at은 교체 시각이 아니다.
- 기존 other_error는 네트워크/영상 제한이 혼합돼 있어 해당 구간 성공률을 확정하지 않는다. 최근 1시간 20회 이상·80% 미만, 또는 최근 15분 내 시도에서 봇 확인 실패 5회 이상 연속이면 IP 관찰 알림을 만든다. 비활성 경로는 제외한다. 하루 30회 이상·60% 미만·다른 활성 경로보다 20%p 이상 낮고 최근 악화도 확인되면 교체 검토로 표시한다. 실제 IP 변경이나 경로 비활성화는 하지 않는다.
- IP 경보는 현재 IP별로 중복을 막는다. 교체/수집 제외 시 이전 사건은 종료하되 복구라고 알리지 않는다. 조회 미확인은 기존 사건을 닫지 않는다. 알림에서 해당 IP 상세로 이동할 수 있으며 푸시 본문에 경로·성공률·연속 실패를 표시한다.
- 화면과 열린 IP 상세는 foreground에서 30초마다 확인한다. 알림은 기존 1분 cron을 사용하며 야간/운영 알림 설정을 따른다. 앱을 다시 설치할 필요 없다.
- 제작 성공률은 24시간 내 접수된 작업 중 완료·실패로 종료된 표본이다. 단계별 시간 집계는 연결하지 않았으며 임의 수치를 표시하지 않는다.
- 결제 확인 알림은 수동 검토 상태를 감지한다. 모든 이용권/PG 정합성을 완전히 대조하는 회계 감사 기능은 아니다.

## 검증

새 기능 20개 테스트: PostgreSQL 통합 집계/중복/알림 정책/재시도/만료/권한/RLS/IP 경계, API 출처/cron 권한/캐시. 타입 검사, lint, production build 통과. 실제 운영 DB는 read-only 연결로 매출/작업/20개 경로와 KRW/JPY/USD 조회 확인.

전체 웹 테스트: 새 기능을 포함해 3503개 통과 당시 기존 편집기 관련 9개 실패. 3개 실패 파일을 현재 운영 원본에서 다시 실행해 같은 9개 실패를 재현했다. 이 변경은 편집기/SNS 컴포넌트를 수정하지 않는다. 이후 추가한 API 검사 5개도 통과했다.
