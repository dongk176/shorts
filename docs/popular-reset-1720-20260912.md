# 조회수 상위·재사용 허용의 수집 회차

사용자 승인: 두 대필터의 오늘 수집 전환을 한국시간 오후 17:20으로 변경한다.
17:10에 시작한 수집을 포함하고, 완료가 늦거나 실패하면 기존 회차를 유지한다.

## 실행 기준

  `a5a9a1fe345b6fa4e0522860814bdf30addbbf0b`.
- 작업 브랜치: `codex/popular-reset-1720-20260912`. 위 운영 커밋에서 분리했다.
- 대상: Vercel `prj_bQyHRVC3Pfzq2dvUnAqEDlw66GOw`, Supabase
  `mvcprswvfybudtopepuj`, `shorts_mvp`. 기존 운영 수집 기능 세 플래그가 true임을 확인했다.
- 운영 DB 읽기에서 2026-09-11 17:10 KST 두 lane의 실제 성공을 확인했다.
  조회수 상위는 17:11:17, 재사용은 17:11:03에 완료됐다.
- 검증은 이 후보 코드와 임시 로컬 PostgreSQL 16에서 수행한다. lab의 별도 코드,
  계정 또는 DB를 운영 검증으로 대신하지 않는다. DB 마이그레이션, 수집 일정,
  할당량, 워커 및 환경변수 변경은 없다.

## 동작

- 두 대필터의 `periodBasis=collected`에만 적용한다. 급상승, 과거 날짜 API,
  기존 최초 발견 기준 API는 기존 날짜 계산을 유지한다.
- 각 대필터는 자신의 17:10 정기 검색 중 성공했고 완료 시각과 17:20을 모두 지난
  가장 최근 회차를 사용한다. 자정과 오전 05:10 검색은 회차를 바꾸지 않는다.
- 회차 시작은 그 검색의 17:10 예정 시각이다. 17:10~17:20 수집분을 제외하지 않는다.
  모든 실제 수집 경로에서 해당 기간에 수집한 영상을 합치는 기존 규칙을 유지한다.
- 오후 검색이 실패/누락/지연되면 이전 회차의 기간 하한을 유지한다. 수집 중 추가된
  영상은 포함될 수 있으나 기존 영상이 시간 경계 때문에 사라지지는 않는다.
  첫 성공 오후 회차가 아직 없다면 보존된 유효 카탈로그를 유지한다.
- 최근 7일은 활성 회차 시작에서 6일 전부터 계산한다. 목록과 숫자가 같은 하한을
  사용한다. 전체는 기간으로 제한하지 않으며, 공개 상태·라이선스·30일 재확인 규칙은 유지한다.
- 기간별 목록 캐시에 회차를 포함해 17:20 이전 결과를 재사용하지 않는다. 지난 회차의
  더보기 커서는 만료 처리한다. 화면을 열어 둔 경우 기존 60초 상태 확인에서 회차 전환을
  감지해 새 목록을 불러온다. 안내 문구는 한국어·영어·일본어로 표시한다.

## 검증

- 관련 테스트 82개 통과: 실제 SQL 조회, 17:20 경계, 지연/실패/누락, 자정 유지,
  오전 추가, 17:10 포함, 조회수 정렬, 전체 보존, 주간 경계, 캐시와 더보기 전환,
  월말·윤년·연말, 급상승 기준 유지.
- 전체 웹 테스트 2524개 통과. 별도 DB/외부 구성이 필요한 85개는 기본 전체 실행에서
  건너뛰며, 이번 변경 관련 PostgreSQL 통합 테스트는 위 별도 실행에서 실제로 실행했다.
- 전체 웹 lint 및 타입 검사 통과.
- 비용: 기존 로컬 자원과 소규모 읽기·웹 후보 빌드/배포만 사용한다. YouTube 검색,
  영상 생성, 새 고정비 자원은 만들지 않는다. 임시 DB는 테스트 후 종료한다.

승격 전에는 실제 운영 SHA를 다시 확인하고, 경로 manifest와 다섯 보호 경로,
후보 작업 생성 preflight를 검증한 동일 배포만 승격한다.
