# 내 배경·템플릿 고정 텍스트 — 관리자 선공개

이 문서는 구현 범위와 배포 절차다. 로컬 검증 성공을 운영 배포·실제 업로드
검증·일반 공개 완료로 간주하지 않는다. 운영 검사 결과를 임의로 `passed`로
작성하거나 이전 릴리스의 결과를 새 이미지에 재사용하지 않는다.

## 구현 범위

- 편집기와 템플릿에서 같은 **내 배경** 선택기를 사용한다. 업로드 성공한
  이미지는 계정의 목록에 보관되고 다른 영상·템플릿에서 다시 선택할 수 있다.
- JPG·PNG·정지 WebP, 원본 3MiB/2,000만 픽셀 이하만 받는다. 실제 디코딩 후
  방향·색상을 정리하고 중앙 기준 1080×1920 WebP로 저장한다. 투명 부분은 검정,
  변환본은 2MiB 이하이다. 외부 URL·임의 S3 키·Base64 저장은 받지 않는다.
- 목록은 100개, 업로드는 분당 10회, 실제 보관 용량은 1GiB 한도이다. 예약과
  동시 업로드도 서버에서 같은 한도를 적용한다.
- 목록에서 제거해도 참조 중인 템플릿·유효한 영상·진행 중 작업은 깨지지
  않는다. 참조와 초안 보호 기간이 끝난 미사용 자산만 30일 유예 후 정리한다.
  교체·기본 배경 복원은 원본 자산을 바로 삭제하지 않는다.
- 템플릿 고정 텍스트는 기존 편집기의 글꼴·색·효과·이동·폭·크기·앞뒤 순서·
  삭제·실행 취소를 공유한다. 20개/각 120자 제한과 기존 스타일 범위는 유지한다.
- 첫 생성과 첫 편집 진입 시 템플릿 문구를 전체 영상 구간으로 복원한다.
  저장 문서·초안의 빈 배열은 삭제 결과이므로 문구를 다시 넣지 않는다.
  템플릿 교체는 `tpl:<templateId>:<textId>` 텍스트만 바꾸고 수동 문구는 보존한다.
- 템플릿·홈 선택·즐겨찾기 카드는 동일한 배경·텍스트 그리기 코드를 사용한다.
  저장 알림과 탭 복귀 시 목록을 새로 읽는다. 생성 요청의 템플릿 버전이
  달라졌으면 작업·사용량 예약 전에 409로 확인을 요청한다.
- 기존 문서/렌더/폰트 버전, 과금, 이용 권한, 3–60분 및 기존 source-range
  자격·4시간 원본/4–60분 선택 구간 정책은 바꾸지 않는다.
- 옛 데이터에 새 필드를 자동 삽입하지 않는다. `textOverlays: []`도 구 Worker가
  모르는 **새 형식**이므로 기능·버전·렌더 증거 검증을 생략할 수 없다.

웹에는 최근 편집 반영 일관성 수정과 로그인 전 업로드 진입 UI가 포함되어 있다.
Worker와 수신기는 각각 위 소스에서 분리한 작업공간으로 빌드한다. 웹에 있는

현재 구현된 Worker 소스는 `ab9bad270c46ab37ba09237d814a155d30831259`,

운영 소스에서 렌더 변경만 분리한 로컬 커밋이며, 운영 이미지로 빌드·등록했다는
뜻이 아니다. 다운로드·설정·수신 서비스·의존성·Dockerfile은 각각의 운영 기준과
동일하다.

## 배포 순서와 중단 조건

1. **기준·불변값 기록:** 현재 웹 SHA, Worker 5개 definition/queue, 실제 편집
   definition, 각 CPU/메모리/네트워크/역할/timeout, 이미지 digest, PO 활성화,
   egress mode, Secret 참조·AWSCURRENT 버전, 20개 route의 비밀값 없는 해시를
   기록한다. 프록시 주소·토큰·Secret 값은 로그나 문서에 남기지 않는다.
2. **기능 OFF로 호환 준비:** 새 자산 스키마와 검증된 후속 인계 마이그레이션만
   파일명을 지정해 적용한다. 두 디자인 공개 플래그는 기존값을 덮어쓰지 않고
   없을 때만 false로 만든다. 새 이미지 경로에 웹 Put/Get, Worker·수신기 Get만
   추가한다. 정리 Lambda·registrar의 필요한 코드만 좁은 변경 세트로 준비한다.
3. **호환 웹 먼저:** 기존 운영 Worker/수신기 연결을 유지한 웹을 무별칭 후보로
   검증한다. 기존 170개 경로가 모두 있고 자산 API 2개만 추가되어야 한다.
   보호 경로와 로그인 전 업로드 UI·최근 편집 수정도 확인한다. 기능은 아직 OFF다.
4. **Worker 후속 릴리스:** 새로운 불변 소스 태그와 정확히 일치하는 빌드/검증
   신뢰 정책을 사용한다. 잠긴 기존 BuildRole을 임의로 넓히거나 기존 태그를
   이동하지 않는다. 기존 AWS 격리 probe·15개 검사와 새 디자인 증거가 모두
   통과해야 registrar가 실제 운영 5개 경로와 편집 렌더 계약을 복제할 수 있다.
5. **공개 보존 인계:** [프로젝트 Worker 후속 업그레이드 절차](project-target-successor-runbook.md)를
   따른다. 기본 rotation의 `kill=true/rollout=0` 동작을 그대로
   실행하지 않는다. 검증된 동일 폰트·4/4 후속 릴리스에만 명시적인 보존 경로를
   사용한다. 신규 접수는 사용량 예약 전 막고, 미제출 작업/outbox/claim을 비운
   다음 기존 경로와 신규 경로의 정확한 identity를 연결한다. 이미 제출된 작업을
   새 워커로 재지정하지 않는다. 실패·시간 경과만으로 접수 제한을 해제하지 않는다.
   관리자 검증은 기존 내부 공개 플래그를 켜는 대신, 검증된 후속 인계에 한정한
   실제 관리자 권한으로 진행한다. 카나리 일시 중지만으로 접수 제한이 풀리지
   않으며, 승격 완료 또는 검증된 원래 연결 복구를 별도로 마쳐야 한다.
   이 단계는 디자인 기능 OFF 상태에서 기존 영상·편집과 새 디자인의 격리
   렌더 증거를 검증한다. 새 디자인의 실제 제품 흐름은 수신기까지 준비된
   뒤 7단계에서 양쪽 경로를 함께 확인한다.
6. **수신기 별도 인계:** [수신기 후속 업그레이드 절차](file-upload-successor-runbook.md)를
   따른다. 기존 세션·대기/발급된 용량·보호된 태스크·ALB 경로까지 비운 뒤
   관리자만 새 수신기를 시험하고, 실제 새 이미지의 9개 검사 결과를 원자적으로
   인계한다. 공개 설정은 유지하고 인계 중 신규 업로드는 무차감 재시도한다.
   릴리스 후보 슬롯은 하나이므로 Worker 승격을 끝낸 후 수신기를 최종 등록한다.
7. **관리자 선공개:** 동일 배포를 재빌드 없이 승격하고, 정확한 Worker·수신기
   증거/연결이 확인된 관리자 화면에서 디자인 모드를 ‘관리자만’으로 바꾼다.
   회사 권리 보유 YouTube 영상과 파일 업로드 각각에서 저장→생성→다운로드→
   재편집→다시 열기를 완료한다. 실제 프레임과 모든 미리보기를 비교한다.
8. **일반 공개:** 위 실영상 확인 후 관리자 스위치만 ‘일반 공개’로 바꾼다.
   다운로드/시각 비교는 자동 DB 검사로 대체하지 않는다. 15분간 생성·편집·
   업로드·5xx/Batch 오류와 처리 시간을 확인한다. 디자인 문제면 **신규 디자인
   사용만 OFF**하고 호환 웹·이미 보관된 자산·진행 중 작업은 유지한다.

일반 Worker 배포, 전체 CDK 배포, 프록시/PO 토큰/Secret 회전, 전체 Vercel 환경
동기화는 이 작업의 배포 방법이 아니다. 필요한 정확한 대상 연결값만 검증해
변경한다. 단발성 무관한 타임아웃으로 전체 시스템을 과거 버전으로 돌리지 않는다.

## 검증 구분

### 자동·로컬 검증

2026-08-31 최종 로컬 `make verify`가 통과했다. 웹 2,158개, 제어 스크립트
195개, 인프라 36개 테스트와 Worker/Lambda 검사·웹 빌드·인프라 합성을
완료했다. 별도 opt-in 격리 PostgreSQL 검사는 자산 보관/정리 20개,
수신기 인계 46개, 프로젝트 인계 76개가 통과했다. 기본 검사에서 이 격리
DB 검사가 skip으로 표시되는 것은 운영 DB에 자동 연결하지 않기 때문이다.

- `make verify`: Worker/Lambda·웹·스크립트·CDK 검사, 웹 빌드와 인프라 합성.
- 실제 디코딩: 정상 이미지, 투명/회전, 손상/확장자 위장, 애니메이션,
  용량/픽셀 초과와 타인 자산 접근 거절.
- 격리 PostgreSQL: 업로드/용량 동시성, 참조·진행 중 작업 보호, 정리 경쟁,
  30일 유예, 후속 수신기 RPC/CAS/구웹 INSERT 차단, 프로젝트 target 인계의
  영구 차단·관리자 제한·승격 후 정확한 연결 고정과 동시 요청.
- 실제 FFmpeg/ffprobe: 새 배경, 20개 글꼴, 앞뒤 순서, 초기 생성↔재편집,
  삭제 후 무수정 재편집의 누락·중복 없음.
- 로컬 브라우저 harness: 한국어/빈 줄, 20개 글꼴 선택 반영, 저장 후 세 카드
  갱신, 공통 보관 목록, 선택 실패 시 기존 이미지 유지, 검증 중 저장 차단,
  기본 배경 복원·실행 취소, 20개 제한 및 OFF 후 기존 디자인 표시.
- 업로드 배경 A→B의 실행 취소/다시 실행, 실행 취소 후 C 선택 시 B 재실행
  기록 제거를 별도 회귀 검사한다.

브라우저 harness는 메모리 API/합성 이미지뿐이며 운영 DB·S3·계정에 연결하지
않는다. 이는 배포 후 실제 영상 E2E 검사를 대신하지 않는다. 자동 브라우저의
range 키 입력은 네이티브 input/change를 만들지 않아 슬라이더·드래그의 실제
손 조작은 관리자 단계에서 추가 확인한다.
