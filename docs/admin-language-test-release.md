# 관리자 언어 제작 시험

실제 운영 웹 `3ee360a0ef0c43dec6fc68e09a4701ab4ecad330`를 기준으로 언어 기능만
통합한다. 일반 제작의 다섯 대상과 기존 편집기 릴리스, 공개 비율은 변경하지 않는다.
운영 AWS는 `181651591905`, DB는 `mvcprswvfybudtopepuj/shorts_mvp`다.
기존 lab 웹·DB·인프라는 이 릴리스의 실행 대상이 아니다.

## 접수와 기존 결과

- 관리자 관리 화면의 활성 설정은 신규 언어 시험 접수만 제어한다. 기본 OFF다.
- 활성 상태의 관리자 제작 화면에서 ‘언어 기능 테스트’를 직접 켠다. 새로고침은 OFF다.
- 유튜브 링크만 지원한다. 영상 언어는 자동/한국어/영어/일본어, 출력은 한국어/영어/일본어다.
- 일반 요청은 언어 시험 설정/릴리스 테이블을 읽지 않는다. 파일 업로드는 기존 경로다.
- 프로젝트 언어·릴리스·대상은 사용량 예약과 같은 트랜잭션에서 저장되고 변경할 수 없다.
- OFF 이후에도 이전 시험 프로젝트는 저장된 릴리스로 편집한다. 기존 프로젝트는 자동 변환하지 않는다.
- 일반 경로의 이미지·폰트 검사는 기존 값으로 유지한다. 시험 경로도 해당 이미지·폰트·소스를 검사한다.
- 다른 언어로 번역한 자막은 기본형이다. 본문 실패는 자막 없이 안내하고, 여유 구간만 실패하면 본문을 보존한다.

## 배포 순서

1. 실제 운영 커밋과 현재 Lambda 코드를 다시 조회한다. 사용자 데이터가 아닌 구조와 등록 정보만 보관한다.
2. 격리 PostgreSQL에서 호환 변경·권한·동시 접수·OFF 이후 편집을 검증한다.
3. 깨끗한 커밋에서 워커 이미지를 빌드한다. 고유한 다섯 제작 정의와 편집 정의를 등록한다.
4. 기존 VPC/서브넷/보안 그룹을 이용한 별도 Fargate 실행 용량과 FIFO 큐를 사용한다.
   최대 8 vCPU로 8 vCPU 작업 하나만 실행하며 유휴 실행 인스턴스는 없다. 일반 큐는 수정하지 않는다.
5. 호환 DB 변경을 적용한다. 시험 설정은 OFF다. 실제 이미지의 합성 렌더·폰트·브라우저 비교 증거를 확보한다.
6. 시험 릴리스와 정확한 대상만 등록한다. 전역 canary/stable 포인터와 공개 플래그는 바꾸지 않는다.
7. 제작 제출기는 기존 코드의 언어 분기만 적용한다. 편집 제출기는 실제 배포된 구버전의
   일반 경로를 유지하도록 `scripts/package-language-test-submitters.py`로 제한된 패치를 만든다.
   입력 코드 해시가 바뀌면 패키징을 중단한다. 환경변수는 그대로 보존한다.
8. 운영 프로젝트의 별도 미승격 후보를 검증하고, 직전 운영 버전을 재확인한 뒤 동일 후보를 승격한다.
9. 관리자 시험 기능만 활성화한다. 신규 테스트 실패 시 이 설정만 OFF하고 기존 결과 연결을 보존한다.

## 검증과 비용 통제

일반 제작/기존 편집, 위조 요청 차단, 중복·동시 접수, 시험 OFF 후 편집·댓글 재생성을 확인한다.
원본 프로젝트 11238은 변경하지 않는다. 같은 원본의 일본어→일본어, 일본어→한국어와
한국어→한국어 새 비교 프로젝트를 순차 실행한다. 제목의 장면 적합성, 댓글 자연스러움,
번역 자막, 저장·재출력·다운로드를 실제 결과로 확인한다. 범용 대체 제목만으로 통과시키지 않는다.

기존 서비스의 종량제 테스트 비용은 이미 승인된 범위다. 최초 비교는 세 프로젝트와 합성
렌더 검증, 필요한 편집 재출력으로 제한한다. 초기 예상은 빌드·Fargate·전사·AI·임시 보관을
합쳐 약 5천~3만원이며 실사용에 따라 기록한다. 무제한 반복하지 않고 각 작업에 제한 시간을
둔다. 유휴 고정비가 생기는 ALB나 상시 서버는 만들지 않는다. 로컬 일회용 DB는 종료한다.
