# SNS·커뮤니티 공통 편집기 구현 및 배포 인계

## 구현 기준

- 운영 조회로 확인한 기준 커밋: `d5c66a96c48b10e9e24aafc7e5ca0626b8da1bc1`.
- 작업 브랜치: `codex/unified-template-editor-20261022`.
- 이번 작업은 로컬 구현·검증만 수행했다. 운영 DB, AWS, 릴리스 등록 및 배포는 변경하지 않았다.
- 일반 편집기를 SNS·커뮤니티에도 사용한다. 본문·해시태그·게시판 이름은 일반 텍스트 레이어로 편집하며, 기존 사진 배경·채널 사진·댓글·레이아웃·구간 편집·되돌리기를 공유한다.
- 자막은 기존 원본 데이터 및 접근 검사에 따른다. 원본이 없는 기능을 새로 생성된 것처럼 표시하지 않는다.
- 템플릿 종류 전환은 SNS/커뮤니티 생성·렌더 정체성을 보존하기 위해 노출하지 않는다.

## 호환성 및 활성화

웹만 배포해서는 새 편집기를 활성화하지 않는다. 아래 두 새 불변 릴리스의 워커를 현재 운영 기준으로 빌드·검증·등록해야 한다.

| 종류 | 새 편집 릴리스 ID |
| --- | --- |
| SNS | `66f640ba-d156-4c90-9c4f-f79038bf9d14` |
| 커뮤니티 | `a576138e-1ddf-4469-8494-252058595705` |

기존 `sns_editor_compatibility` 검사의 소스 커밋·이미지 digest·폰트 manifest·지원 생성 릴리스 검증을 유지하고, 새 릴리스에는 `details.unifiedTemplateEditorVersion: 1`을 추가로 요구한다. 이 증거 없이 capability를 활성화하지 않는다. 업로드 배경은 전용 SNS 검사에 연결된 exact-image custom-design 증거도 필요하다. 일반 편집기의 전역 5개 lane 등록은 변경하지 않는다. 전용 검사는 런타임 이미지·소스·폰트, 버전이 있는 S3 증거, SNS/커뮤니티 실제 렌더, 기존 20개 폰트 custom-design 합성 검사 및 해당 소스의 데스크톱/모바일 브라우저 검증을 모두 요구한다.

기존 고정 편집 워커와 릴리스를 보존한다. 새 릴리스가 준비되지 않으면 기존 편집기를 사용한다. 새 문서는 `unifiedEditorVersion: 1`로 식별하며 이전 워커로 보내지 않는다. 등록된 이미지 digest, revisioned ARN 및 실제 실행 워커의 내장 릴리스 증거를 확인해야 한다.

공통 렌더러의 텍스트/채널 배치와 폰트를 사용하므로 예전 고정 SNS 출력과 픽셀 단위로 동일하지 않다(본문·채널 기본 가운데 정렬 등). 기존 영상은 사용자가 편집을 적용하기 전까지 유지된다. 사진 기능의 범위는 기존 배경 사진과 채널 사진이며 임의의 다중 사진 레이어를 새로 추가한 것은 아니다.

## 검증

- `make lint`: 통과.
- 웹/API 관련 6개 파일의 테스트 243개: 통과.
- 렌더러·v4·기존 SNS·통합 SNS 테스트 101개: 통과. FFmpeg/ffprobe 합성 영상 테스트 포함.
- 웹 production build: 통과. 기존 선택 의존성 `canvas` 경고는 남아 있으나 빌드 실패 없음.
- 한국어/영어/일본어 × 5개 비율 × SNS/커뮤니티 초기 문서 및 스키마 검사: 통과.
- Chrome 데스크톱: 본문·색상·채널 사진·배경 사진·되돌리기·저장 및 저장 문서 재열기 확인.
- Chrome 390×844 반응형 viewport: 본문 수정·되돌리기·타임라인 확대·자막 켜기·저장 확인.
- 로컬 API fixture에서 실제 공통 검증기 및 Python 렌더러를 연결해 SNS/커뮤니티 4초 1080×1920 H.264/AAC 출력 확인.

검증은 운영 DB/AWS가 없는 합성 프로젝트 구성이다. 운영 권한·저장소·큐·원격 렌더까지 검증했다는 의미가 아니다. 실제 모바일 기기의 터치 제스처 및 모바일 저장 문서 재열기는 미확인이다.

배포 시 최신 promoted 운영 커밋을 다시 확인하고 필요한 변경만 적용한다. 새 워커의 실제 배포 증거와 호환성 검사를 확보하고, unaliased 웹 후보에서 필수 5개 경로 및 편집→저장→렌더→재열기 흐름을 확인한 후 동일 후보를 승격한다. 기존 publishing 유지보수 게이트와 이전 프로젝트의 워커 참조를 유지한다.

## 배포 준비 보완

운영 조회에서 기존 DB 승인 함수와 편집 제출기의 고정 허용 목록을 확인했다. 새 릴리스 두 개를 추가하면서 capability 증거를 요구하는 마이그레이션 및 제출기 패치를 추가했다. 제출기는 조회한 실제 운영 ZIP을 기준으로 `_sns_editor_compatible` 함수만 교체하고 나머지 코드의 AST 및 파일을 보존한다. 기존 운영 이미지와 현재 소스의 Dockerfile·requirements가 동일하므로 검증된 digest 기반에 현재 커밋의 worker 소스를 전체 복사해 각 전용 이미지를 빌드한다. 클라우드 검증은 1200초 제한·단일 시도의 합성 작업 두 개로 시작하며 예상 비용은 USD 5 이내, 새 유휴 고정비는 없다.
