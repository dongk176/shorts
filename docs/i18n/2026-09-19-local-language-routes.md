## 동작

- `/` = 한국어, `/en` = 영어, `/jp` = 일본어. 일본어 내부 코드는 `ja`다.
- middleware가 같은 페이지로 연결한다. 페이지 복사나 새 사용자/DB/PG 계정 분리는 없다.
- 언어 선택은 현재 페이지·쿼리·앵커를 유지한다. 예: `/jp/pricing` → `/en/pricing`.
- 공통 링크와 화면 이동은 언어를 유지한다. OAuth 시작·콜백 API 주소는 유지하고 `next`만 해당 언어로 전달한다. 결제 완료/실패의 화면 복귀 URL도 같은 원칙이며 PG, 금액, 구독 소속, 승인·정산 로직을 바꾸지 않았다.
- 쿠키보다 페이지 주소가 우선한다. 영어 선택 후 새 탭에서 `/`에 접속하면 한국어다.
- I18nProvider를 언어마다 새로 마운트하지 않는다. 기존 문구 변환기는 이전 번역만 복원해 한국어/영어/일본어를 오가도 작성 중인 React 상태를 유지한다.
- 기존 새 제작 기본값인 원본 자동 감지 → 사이트 언어를 URL 언어와 연결한다. 이미 선택한 출력 언어 및 저장된 프로젝트 언어를 바꾸지 않는다. 기존 언어 기능 권한/워커 제한은 유지한다. 파일 업로드 제작의 한국어 제한도 이 작업에서 확대하지 않았다.
- API, 인증 콜백, 관리자, 정적 파일, 초대 링크, publishing 실험은 언어 접두사를 붙이지 않는다. `/jp/api/...`, `/en/admin/...` 등은 404다.
- 검색용 canonical/hreflang 및 공개 페이지 sitemap에 언어별 주소를 반영했다. 기존 번역 범위를 사용하며 모든 블로그 글·가이드북 본문이 새로 번역됐다는 의미는 아니다.
