# 첫 화면의 한국어 노출 수정

## 대상

- 기준 커밋 `e8f739fc`, 브랜치 `codex/locale-routes-local-20260919`의 후속 로컬 변경.
- 작업 경로 `/Users/gimdongmin/shorts-clean/.tmp/locale-routes-local-20260919`.
- 운영·lab 서비스 및 YouTube 업로드 실험은 수정하지 않았다. 배포하지 않았다.
- 사용자가 블로그 본문·PDF·과거 약관·일부 기업 전용 화면의 한국어 유지를 허용했다. 해당 자료는 이번 이관 대상에서 제외한다.

## 원인과 변경

기존 JSX가 한국어로 먼저 렌더링되고 `LegacyTranslationBridge`가 브라우저 effect에서 문구를 바꿔, 자바스크립트 로딩 전에 한국어가 노출됐다.

- 기존 사전을 사용하는 `createUiText(locale)`와 `useUiText()`를 추가했다. 각 화면의 표시 문구와 접근성 속성을 렌더링하는 자리에서 `ui(...)`로 변환한다.
- 서버 페이지는 요청의 언어를, 클라이언트 컴포넌트의 서버 렌더링과 첫 hydration은 `I18nProvider`의 요청 언어를 사용한다. 페이지를 가리거나 추가 대기 시간을 넣지 않는다.
- 메인·제작/편집·템플릿·설정·프로젝트·요금제·공개 안내의 한국어 JSX 및 데이터 기반 UI 문구를 이관했다. 이미 언어별로 작성된 문구와 기존 메시지 키는 그대로 재사용한다.
- 요금제 카드/비교표, 템플릿 도구 이름, 배경 선택 접근성 안내 등 데이터에서 오는 문구도 처음 렌더링할 때 변환한다.
- 언어별 페이지 복제, 새로운 번역 의존성, locale 변경에 따른 컴포넌트 강제 재생성은 없다. 금액·결제 동작·폼 상태·영상 제작/저장 로직은 변경하지 않았다.
- 사용자 영상 제목·자막·채널명·파일명은 원문을 유지한다. UI 사전에 있는 단어와 동일한 사용자 원문도 변환하지 않는 회귀 검사를 추가했다.
- 기존 DOM 브리지는 미이관 레거시 영역의 호환용으로 남긴다. 신규 UI는 렌더 시 `t(...)` 또는 `ui(...)`를 사용해야 한다. 이번 결과는 브리지 실행 후의 화면을 검사한 결과가 아니다.

## 검증 구성과 결과

로컬 웹 `http://127.0.0.1:3219`, 전용 PostgreSQL `locale_routes_local`(55443), 전용 GoTrue(55444), 인증 경로 어댑터(55445)를 사용했다. 185개 기존 마이그레이션과 합성 계정/영상 분석 정보만 사용했다. 외부 결제·메일·영상 생성 및 AWS 작업을 실행하지 않았다. 별도 유료 리소스를 추가하지 않았다.

1. **첫 HTTP 응답 42개**: JavaScript를 실행하지 않고 초기 HTML의 본문 텍스트 및 `aria-label`/`placeholder`/`title`/`alt`/`data-tooltip`을 검사했다. `script`, `head`, 사용자 콘텐츠 보호 영역은 제외했다. 42개 모두 HTTP 200이며 검사 대상에 한글 및 브리지가 나중에 변환해야 할 문구가 없었다.
   - 비로그인 30개: 영어·일본어 각각 메인, 요금제, 템플릿, 프로젝트, FAQ, 고객센터, 가이드북, AI 쇼츠 안내, 비교 페이지, PRIVATE, 인기 영상, 현재 이용약관·개인정보·구매약관·환불정책.
   - 로그인 12개: 영어·일본어 각각 메인, 설정, 요금제 관리, 결제/사용 내역, 프로젝트, 새 템플릿 편집기.
2. **브라우저**: 영문 FAQ, 일본어 메인, 실제 로컬 로그인/첫 설문, 합성 분석 정보의 일본어 제작 설정, 일본어·영어 요금제 화면을 확인했다. 일본어→영어 전환에서 입력한 URL과 요금제 12개월 선택이 유지됐다. 첫 설문의 진행 단계 접근성 문구도 언어에 맞춰 보완했다. 검증 탭에서 hydration 오류 기록은 발견되지 않았다.
3. **회귀 테스트**: `components`, `app`, `lib/i18n`, 템플릿 설정 및 Toss checkout 관련 검사 134개 파일, 966개 테스트 통과. 기존 조건부 skip 1개 파일/11개 테스트는 실행되지 않았다.
   - 신규 8개 테스트는 effect가 실행되지 않는 서버 렌더링으로 영·일 요금제/가이드, 편집기 UI, 접근성 라벨, 한국어 원문 유지, 사용자 캔버스 콘텐츠 보존을 검사한다.
   - 구조 검사 중 한국어 JSX 리터럴을 기대하던 항목은 새 렌더 함수/기존 메시지 키에 맞춰 갱신했다. 조건·배치·권한 검사 자체는 유지한다.
4. **최종 빌드**: Next.js 배포용 빌드, ESLint 및 TypeScript 검사 통과(exit 0). 기존 BudouX 선택적 `canvas` 경고와 DB 없는 빌드 단계의 홈 초기 상태 fallback은 유지된다. 실제 화면 검증은 별도 로컬 DB/Auth에 연결한 개발 서버에서 수행했다.
5. `git diff --check` 통과.

검증 중 개발 서버와 빌드를 함께 실행했을 때 조회 지연이 발생해, 전용 개발 서버를 재시작하고 초기 응답 검사를 순차 실행했다. 최종 HTTP 결과는 재시작 후 완료된 42개 응답 기준이다. 마지막 배경 선택 안내 보완 중의 누락된 번역 함수 참조는 테스트에서 발견해 수정했으며, 최종 966개 통과는 수정 후 결과다.

## 한계와 정리

- 원본 영상/PDF 안의 글자, 한국어 유지가 허용된 자료, 외부 PG 화면/메일, 일반 문서의 head 메타데이터 전체를 이 검사로 보증하지 않는다.
- 결제 이력이 없는 합성 계정 기준이다. 실제 결제·해지·환불 또는 모든 유료 계정 상태를 실행한 검증이 아니다.
- 운영에 반영하려면 현재 승격된 운영 커밋을 기준으로 별도 후보를 만들고 기존 배포 검증을 거쳐야 한다.
- 검증용 브라우저 탭, 웹·인증 어댑터, 이 작업의 DB/Auth 컨테이너를 종료했다. 다른 작업의 로컬 리소스는 유지했다.
