## 서비스 동작

| 목록 | 확대 후 한국시간 수집 | 검색/일 | 기본 목록 |
|---|---|---:|---|
| 인기 급상승 | 홀수 시 정각, 2시간 간격 | 0 | 최근 발견 24시간 합집합. 최신 성공 수집의 영상 우선 |
| 조회수 상위 | 05:10, 17:10 | 40 | 모든 경로에서 누적된 현재 일반 라이선스 영상, 최신 확인 조회수순 |
| 재사용 허용 | 05:10, 17:10 | 20 | 모든 경로에서 누적된 현재 CC 영상, 최신 확인 조회수순 |
| 기존 무료 소재 | 17:40 | 30 | 기존 무료 소재 수집·표시 경로 유지, CC는 재사용 목록에도 포함 |

확대가 꺼져 있으면 기존 17시 일일 주기를 유지한다. 새 구조가 켜져 있는 일일 모드에서는 일반 검색 40회, CC 10회, 무료 30회를 한 번씩 실행한다. 같은 예정 시간의 중복 요청과 구형 개별 수집 엔드포인트의 중복 실행을 막는다. 기존 일일 작업은 확대 주기가 검증되어 켜졌을 때 실행하지 않는다.

급상승 날짜 선택은 한국시간 하루 동안 등장한 영상의 합집합이다. 당시 조회수·순위는 재현하지 않는다. 과거 화면은 최신 확인 조회수순이며, 수집 기록 없음/일부 수집 기록/정보를 확인할 수 없는 영상 안내를 제공한다. 미래 날짜는 선택할 수 없다. 과거 일일 수집은 실제 1회 기록으로 이행한다.

다른 두 목록의 오늘/최근 7일은 최초 발견의 한국시간 날짜로 계산한다. 조회수 갱신·재등장·라이선스 변경으로 최초 발견일을 갱신하지 않는다. 로그인·유료 권한과 필터 사용 기록을 유지하며, 선택 날짜도 사용 기록에 남긴다.

화면을 보는 동안 순서는 자동 변경하지 않는다. DB 상태를 60초 간격으로 확인해 새 목록 버튼을 제공한다. 급상승 성공 수집이 3시간 이상 지연되면 현재 급상승 표시를 중단한다.

## 저장·요청 구조

- `youtube_catalog`: 영상당 최신 정보 한 행. 내부 해시 ID, 최초 발견, 실제 급상승 발견, 전체 정보 확인, 최근 사용, 다음 재확인 시점을 분리한다.
- `youtube_collection_runs`: 종류·예정 슬롯별 실행, 실제 시작/종료, 성공/부분 실패/실패와 페이지 수.
- `youtube_collection_run_days`: 실행 중 영상이 실제 관측된 한국시간 날짜. 자정을 넘긴 실행도 해당 날짜에 수집 기록으로 표시하며 영구 보존한다.
- `youtube_trending_days`: 날짜·내부 영상 ID별 영구적인 자체 발견 기록.
- `youtube_trending_run_items`: 최근 실행의 구성원 ID. 모든 수집 경로의 임시 호환 목록 생성에도 사용하며 48시간 후 정리한다.
- `youtube_list_versions`: 필터별 ID 순서만 고정한다. 48시간 만료이며, 같은 정보 세대의 목록을 공유한다. 현재 공개 상태·라이선스·유효기간은 버전보다 우선한다.
- `youtube_search_positions`: CC 카테고리 7개의 조건과 다음 페이지. 최근 7일 탐색 3개는 순환한다. 유효하지 않은 토큰은 다음 실행에서 초기화하며 같은 실행에서 다시 검색하지 않는다.
- `youtube_catalog_imports`: 이전 수집별 50개 단위 이행 위치. 호출당 최대 500개, 완료된 위치부터 재개한다.
- `youtube_quota_attempts`: 실제 요청 전에 원자적으로 확보한 사용량. Google 프로젝트/PT 날짜/검색 또는 일반/목적별로 기록한다. 실패·중단된 요청도 반환하지 않는다. API 키나 API 응답 원문은 기록하지 않는다.
- `youtube_quota_verifications`: 키 지문에 연결한 운영 할당량 확인 근거와 이행 대조·확대 시점. 공개 API에서 접근할 수 없다.

한도는 검색 합계 90회(일반 40/CC 20/무료 30), 일반 합계 9,000유닛, 그중 백그라운드 최대 3,000유닛이다. 프로젝트와 `America/Los_Angeles` 날짜별 DB 잠금으로 동시 요청을 직렬화한다. 원본 확인에는 백그라운드와 별개로 최소 6,000유닛을 남긴다.

재확인은 15분마다 최대 12페이지×50개로 실행한다. 초기 약 5만 개를 하루 안에 처리할 수 있는 상한이며 실제 처리량은 배경 예산·API 장애에 따라 달라진다. 25일 경과, 최근 사용, 상위 조회수, 오래된 확인 순으로 우선한다. 실패한 묶음은 한 시간 뒤 다시 대상이 된다. 30일이 지난 정보는 조회에서 제외하며 정리 작업이 API 식별자·정보를 폐기한다. 내부 해시와 자체 날짜 기록만 남긴다. 정상 응답에서 삭제·비공개 등이 확인되면 비노출 처리한다. 연결 실패, 잘못된 JSON, 불완전한 공개 영상 정보로 일괄 삭제하지 않는다.

원본 URL 확인은 보통 `videos.list` 1 + `channels.list` 1이다. 이때 확인한 라이선스 변경도 기존 목록에 반영하지만, 조회수 등을 확인하지 않은 부분 확인으로 전체 정보의 30일 기한을 연장하지 않는다. 생성 요청의 기존 15분 분석 결과 재사용, 자막·구간 선택·렌더·재렌더 경로는 유지한다. 원본 확인 실패는 생성 시간·결제 차감 전에 끝난다. 원본 파일 영구 보관은 추가하지 않는다.

## 적용 스위치

모두 기본값이 꺼짐이다. DB 마이그레이션 전에 켜지 않는다.

| 설정 | 역할 |
|---|---|
| `YOUTUBE_DISCOVERY_ENABLED` | 계측·새 수집 저장·정보 재확인 사용. 꺼져 있으면 기존 경로 |
| `YOUTUBE_QUOTA_PROJECT_ID` | 실제 API 키 소유 Google 프로젝트 ID. 임의 이름/추정값 금지 |
| `YOUTUBE_CATALOG_READS_ENABLED` | 새 누적 목록·달력 조회 사용 |
| `YOUTUBE_CATALOG_BACKFILL_ENABLED` | 관리자의 제한된 이행 요청 허용 |
| `YOUTUBE_LEGACY_SNAPSHOT_CLEANUP_ENABLED` | 옛 중복 API 정보 정리의 별도 잠금. 최초 승격까지 끄며 복원·최종 대조 후에만 해제 |
| `YOUTUBE_DISCOVERY_EXPANDED` | 확대 주기 요청. 검증 DB 조건도 모두 맞아야 실제 실행 |

확대는 환경 설정만으로 켜지지 않는다. 실제 키의 SHA-256 지문, 검색 일일 한도 100 이상, 일반 일일 한도 10,000 이상, 공유 사용처 확인, 이행 대조 완료, 확대 시점이 같은 프로젝트의 확인 행에 있어야 한다. 값이 누락되거나 키가 바뀌면 기존 일일 모드로 유지한다. 다른 클라이언트의 사용량은 이 서비스의 계측만으로 알 수 없으므로, 예약 예산과 함께 Google Console 수치를 확인한다. 공유 사용처까지 합쳐 실제 한도에 들어오는 보수적인 일일 상한을 확인해야 `other_clients_reviewed`를 기록한다. 기본 한도에서 다른 사용처가 검색 10회 또는 일반 1,000유닛의 여유를 초과할 수 있으면 이 배분으로 확대하지 않는다.

## 운영 전환 절차

### 기존 데이터 보존: 2026-09-09 추가 확정

첫 운영 전환은 **복사·대조 후 읽기 전환**으로 진행한다. 원본 테이블을 비우거나 재생성하지 않는다. 백업 파일이 있다는 사실만으로 통과시키지 않고, 복원 가능성과 이행 결과를 확인한 뒤 진행한다.

- 첫 DB 변경 전에 현재 운영 DB의 실제 식별자, 일관된 복구 지점, 백업 위치·시각·무결성 값, 복원 절차를 기록한다. 기존 자원에서 격리 복원하여 스키마와 데이터 대조가 가능한지 확인한다. 운영에 백업을 덮어써서 복원을 시험하지 않는다. 복구 가능성이 미확인이면 운영 DB 이행을 시작하지 않는다.
- 기존 수집 작업의 정리 동작도 고려한다. 이전 무료 소재 수집기는 만료 실행을 삭제하므로, 기준 자료 확보부터 새 저장 경로 전환까지 수집·정리 실행의 중첩을 막고 실행 중 작업이 끝났는지 확인한다. 복사 도중 생성된 실행은 최종 대조 범위에 추가한다. 사용자 제작을 중단하거나 작업·결제 데이터를 되돌리는 방식으로 처리하지 않는다.
- 기준 자료에는 출처별 실행/행 수, 고유 영상 집합, 영상별 최초 발견 시각, 한국시간 날짜별 급상승 집합을 포함한다. 총개수만 비교하지 않고 ID별 대응과 날짜 연결을 전수 대조한다. 실패 실행에 남은 행 등 자동 이행 대상에서 제외된 원본도 따로 조사하며, 설명되지 않은 원본 행은 정리 대상에 넣지 않는다.
- 누락·최초 발견일 오류·날짜 연결 누락은 각각 0건이어야 한다. 삭제·비공개·라이선스 변경으로 표시가 달라진 영상은 정상 API 확인 근거와 자체 이력의 대응을 별도로 기록한다. 통신 실패를 삭제로 분류하지 않는다. 이 확인은 코드 테스트로 대체할 수 없는 실제 운영 데이터 검사다.
- `YOUTUBE_LEGACY_SNAPSHOT_CLEANUP_ENABLED=false`를 이행·최초 후보 검증·승격 동안 유지한다. `backfill_verified_at` 기록이나 주기 확대만으로 옛 원본 행 정리를 허용하지 않는다. 정리를 별도로 켜더라도 코드가 당시의 이행 대조 결과를 다시 검사한다. 새로 만든 임시 호환 목록의 기존 48시간/무료 3일 만료는 이 잠금과 별개다.
- 사용자·결제·구독·프로젝트·생성 쇼츠·기존 파일과 그 참조는 이번 이행 대상이 아니다. 관련 삭제·초기화·파일 이동을 하지 않으며 마이그레이션 SQL의 쓰기 범위를 확인한다. 복귀는 기능 스위치/검증된 이전 배포로 실행한다. 새 자체 영상·날짜 기록을 삭제하거나 DB 전체를 과거로 덮어써 배포 이후의 작업을 잃게 하지 않는다.
- 영구 보존 대상은 자체 발견 이력과 이를 최신 정보로 제공하는 누적 목록이다. YouTube API에서 받은 옛 응답을 무기한 보관하는 의미가 아니다. 30일 갱신·폐기 규칙은 유지한다. 이행용 원본과 백업에도 기존 데이터의 나이를 기준으로 보존 기한을 기록하고, 검증·정리를 무기한 미루지 않는다. 백업을 만들거나 복원했다고 API 데이터의 갱신 기한이 새로 시작되지 않는다.

아래 절차의 운영 백업·복원·전수 대조는 아직 미실행이다. 잠금 추가를 운영 보존 검증 완료로 간주하지 않는다.

1. 실행 시점에 현재 승격 커밋을 다시 조회한다. 다른 운영 변경이 있으면 그 커밋을 기준으로 이 변경만 옮기고 검증한다. `docs/execution-boundaries.md`의 실제 계정·프로젝트·DB·워커 리비전 조건을 확인한다. Lab 원격 작업은 기존 lab 작업트리의 경계 검사를 먼저 통과해야 한다.
2. `202609090001_youtube_discovery_catalog.sql`을 검증된 대상에 적용한다. `public`은 변경하지 않는다. 서버 SQL 역할에 필요한 테이블/함수 권한을 확인한다. Lab 적용은 기존 경계·스키마 전환 도구를 사용하며, 이 운영 체크아웃을 그대로 lab에 배포하지 않는다.
3. 실제 키의 소유 프로젝트를 확인해 `YOUTUBE_QUOTA_PROJECT_ID`를 설정한다. 실제 일일 한도, 버킷 종류, 같은 프로젝트의 다른 사용처와 그 사용량을 기록한다. 이 확인 없이는 확대하지 않는다.
4. 최초 계측은 PT 할당량 초기화 이후 해당 날짜의 기존 미계측 요청이 없고 이전 수집도 실행 중이 아님을 확인한 뒤 시작한다. 계측·새 저장만 켜고 읽기/확대는 꺼둔다. 성공 수집은 기존 읽기를 위한 임시 호환 스냅샷도 만든다. 운영 화면에서 목적별 계측, 실패, 남은 한도를 확인한다.
5. 이행을 켜고 동일 출처·관리자 인증·JSON 요청으로 `POST /api/admin/youtube-discovery/backfill`을 순차 호출한다. 응답의 `done=true`까지 반복한다. 실제 API 요청을 동반하므로 시작 전에 묶음의 범위·예상 사용량·비용을 기록하고 기존 묶음당 10,000원 한도를 따른다. 여러 호출을 임의로 별도 예산 묶음으로 나누지 않는다.
6. `GET /api/admin/youtube-discovery`의 `backfill` 대조를 확인한다. 이전 정상 목록의 영상 누락, 최초 발견일 오류, 날짜 연결 누락, 미처리 실행, 30일 경과 정보가 없어야 한다. 오래된 정보는 이행 과정에서 재확인한 뒤 저장하며, 확인 불가 영상은 자체 기록으로만 남긴다. API 실패 시 해당 묶음의 이행 위치를 넘기지 않는다.
7. 대조 결과와 Google 확인 근거를 보존한 다음 해당 프로젝트의 `backfill_verified_at`을 기록한다. 이행 스위치를 끈다. 옛 중복 API 정보 정리는 `YOUTUBE_LEGACY_SNAPSHOT_CLEANUP_ENABLED=false`로 잠근 채 승격한다. 복원 검증·최종 대조 증거와 API 데이터 보존 기한을 확인한 별도 정리 단계에서만 잠금을 해제한다. 새 호환 스냅샷의 48시간 만료(무료 소재는 기존 3일)와 날짜별 자체 기록의 영구 보존은 유지한다.
8. 별칭 없는 후보 배포에서 새 읽기를 켜고 세 목록·달력·권한·생성 경로를 검증한다. `/`, `/guidebook`, `/pricing`, 관리자, 편집기 경로 및 라우트 manifest를 비교한다. 기존 작업 승인 사전 검사에서 운영 DB/AWS/현재 배포와 워커 지문이 모두 일치해야 한다. 후보에 publishing/content-calendar 실험이 포함되지 않았는지 확인한다.
9. 검증한 **동일 후보 배포**를 재빌드 없이 승격한다. 확인된 프로젝트의 `expanded_at`과 확대 스위치를 설정한다. 최초 계측 활성화는 PT 할당량 초기화 직후, 이전 수집이 실행 중이지 않고 그날의 기존 미계측 사용량이 없는 것을 확인한 뒤 진행한다. 계측을 시작하기 전 소비량은 새 DB 사용량에 자동 포함되지 않으므로, 이 확인 없이 당일 확대를 켜지 않는다. 이미 하루 전체를 계측하고 있다면 기록된 잔여 예산 안에서 전환한다. 공유 사용처의 사용량도 별도 확인 근거를 유지한다.
10. 실제 Google 수치와 서비스 계측을 대조하며 목적별 예산, 수집 성공·지연, 25일 경과·재확인 대기를 확인한다. 운영 확인 행을 프로젝트/키 변경 시 재검토한다.

현재는 1의 로컬 구현·검증만 수행했다. 운영 DB 이행, 후보 배포, 승격, 확대 활성화는 실행하지 않았다.

## 복귀

- 수집 확대만 중지: `YOUTUBE_DISCOVERY_EXPANDED=false`. 다음 일일 수집은 새 저장 구조로 기존 주기를 사용한다.
- 화면만 복귀: `YOUTUBE_CATALOG_READS_ENABLED=false`. 최근 성공한 호환 스냅샷으로 기존 목록을 제공한다. 최근 48시간 정상 스냅샷이 있는지 먼저 확인한다.
- 계측/저장까지 중지해야 할 때만 `YOUTUBE_DISCOVERY_ENABLED=false`를 사용한다. 이후에는 구형 코드의 동작이므로 새 한도 보호·재확인도 중지된다는 점을 운영 기록에 남긴다.
- 어떤 복귀에서도 `youtube_catalog`, `youtube_trending_days`, 이행 이력은 삭제하지 않는다.

## 검증 재현

로컬 임시 PostgreSQL 16을 사용한다. 테스트는 URL의 호스트가 `127.0.0.1` 또는 `localhost`이고 DB 이름이 `youtube_discovery_test`인 경우만 허용한다. 이 격리 DB의 `shorts_mvp` 테스트 스키마를 초기화한다. 운영 `.env.local`을 복사하지 않는다.

```sh
docker run --name easycut-youtube-discovery-test --rm -d \
  -p 127.0.0.1:55439:5432 \
  -e POSTGRES_PASSWORD=discovery-local-only \
  -e POSTGRES_DB=youtube_discovery_test postgres:16

YOUTUBE_DISCOVERY_TEST_DATABASE_URL=postgres://postgres:discovery-local-only@127.0.0.1:55439/youtube_discovery_test \
  npm --prefix web test -- lib/youtube-discovery-postgres.test.ts \
  app/api/youtube/popular/route.test.ts app/api/cron/youtube-daily/route.test.ts

make lint
make verify
docker stop easycut-youtube-discovery-test
```

통합 검증은 급상승 재등장/24시간 만료, 한국시간 자정/월말, 일일 과거 기록, 실패 날짜, 누적/라이선스 변경, 안정적인 페이지 이동/커서 만료, 동시 한도·중복 슬롯, CC 토큰 재개/만료, 불완전 응답의 비삭제, 30일 폐기, 원본 확인 2유닛, 이행·대조·정리, 5만 건 목록 생성·재사용을 포함한다. 5만 건 검증은 운영과 같은 쿼리 10초 제한으로 수행한다. 브라우저에서는 실제 달력 컴포넌트에 모의 월별 응답을 연결해 데스크톱/390px 모바일, 날짜 선택, 미래 날짜 차단, 일본어 전환을 확인했다. 이는 운영 인증·배포의 확인을 대신하지 않는다.

공식 기준: [YouTube 할당량](https://developers.google.com/youtube/v3/determine_quota_cost), [API 데이터 갱신·보존](https://developers.google.com/youtube/terms/developer-policies#e.-handling-youtube-data-and-content), [Vercel 예약 작업](https://vercel.com/docs/cron-jobs/quickstart).

- 5만 건 목록 생성과 재사용: DB 쿼리 10초 제한으로 통과. 통계가 없는 새 DB에서도 반복 전체 탐색이 발생하지 않도록 ID 조회 순서를 고정했다.
