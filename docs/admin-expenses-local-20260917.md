## 기능

기존 어드민 `결제·재무 → 매입·비용 관리` (`?tab=expenses`)에 통합했다.

- 인건비 / 외주비 / 서버·인프라 / AI·소프트웨어 / 광고·마케팅 / 수수료 / 사무·운영 / 기타.
- 모든 비용·지급·외화 금액 수기 입력. 자동 비용 수집·자동 지급·급여/세액 계산 없음.
- 원화 총액, 귀속월, 지급 예정일, 운영/테스트/공통 구분, 메모, 반복 여부.
- 하나의 비용에 여러 실제 지급 건을 기록. 미지급/일부 지급/지급 완료는 수기 지급 내역에서 계산.
- 급여 총액과 실수령액 송금/공제액 납부를 분리 기록하여 총비용 중복 합산 방지.
- 예상 초안은 확정 비용과 미지급액에 포함하지 않는다. 다음 달 복사는 지급/증빙/예정일을 비우며 직접 저장해야 반영된다.
- 월별 확정 비용, 선택월 실제 지급액, 선택 귀속월의 현재 미지급 잔액, 증빙 누락. 과거 월말 잔액을 재구성하는 회계 장부는 아니다.
- 귀속월/지급월, 분류, 상태, 텍스트, 증빙 누락, 삭제 내역 조회.
- 현재 목록 범위의 XLSX(비용·지급·집계 기준 3개 시트)와 CSV(비용 내역) 다운로드. 수식 주입 방지.
- 증빙 PDF/PNG/JPEG/WebP 최대 5개, 비용당 합계 2MB. 소량의 비공개 증빙을 기존 PostgreSQL bytea로 저장하여 새 클라우드 자원/공개 URL이 필요 없다.
- 수정 전후 감사 이력, 삭제 내역 보존. 제거한 과거 증빙도 권한 검사 후 이력에서 다운로드 가능.

## 권한·저장

- 기존 `requireAdminUser()`에 더해 `admin_expense_access`에 등록된 사용자만 메뉴/API/증빙 접근 가능.
- 초기 migration은 기존 `is_admin` 운영자 `dmsthaalcls@gmail.com`의 행에만 재무 권한을 부여한다. 이메일만으로 런타임 권한을 얻을 수 없다. 운영 적용 전 실제 운영자 식별·권한을 반드시 재확인한다.
- 재무 테이블은 RLS를 켜고 public/anon/authenticated 접근을 차단한다.
- 모든 쓰기는 동일 출처 JSON, 최대 본문 크기, 엄격한 입력 검사를 거친다.
- 저장 요청 ID와 내용 해시로 재시도 중복을 방지하고, 버전 검사·행/요청 잠금으로 동시 수정 덮어쓰기를 차단한다.
- 비용·증빙·감사 로그는 동일 트랜잭션. 증빙 형식·크기·원래 비용 소속을 서버에서도 검사한다.
- 비용 삭제는 논리 삭제. 이력/증빙 유지. 읽기·다운로드·오류 응답 모두 private/no-store.
- 화면의 중복 경고는 현재 조회한 내역 기준 보조 기능이다. 같은 금액의 다른 실제 비용은 사용자가 확인 후 저장할 수 있다.

## 나중에 템플릿 작업과 합칠 때

1. 그 시점의 실제 운영 승격 커밋을 다시 조회하고, 그 기준의 격리 후보에 이 브랜치의 기능 변경과 승인된 템플릿 변경만 함께 적용한다. 이 작업트리 전체를 과거 기준 그대로 배포하지 않는다.
2. 템플릿 관련 기능 파일은 수정하지 않았다. 기존 파일 변경은 어드민 `page.tsx`, `admin-shell.tsx` 및 메뉴 회귀 테스트다. 기존 모든 메뉴·운영 설정·편집기 제어를 보존한다.
3. 새 migration `202609170010_admin_expenses.sql`은 아직 운영에 적용하지 않았다. 실제 프로젝트/DB/스키마/초기 재무 사용자 식별을 확인하고, 이 migration만 검토하여 적용한다. 기존 migration 전체를 재실행하지 않는다.
4. 실제 후보에서 인증된 재무 운영자와 일반 관리자의 메뉴/API/증빙 권한을 검증한다. 로컬 fixture나 `output/local-preview`는 포함하지 않는다.
5. 보호 경로 manifest 비교, 미완성 publishing 실험 제외, unaliased 후보 검증 후 동일 배포 승격이라는 기존 릴리스 절차를 유지한다. 이번 요청은 배포를 명시적으로 제외했다.
