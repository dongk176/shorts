# 파트너 크리에이터 지원 구현·운영 기록

## 구현 범위

- 신청 화면: `/creator-support`. 기존 Google·Kakao 로그인 경로와 `next` 복귀를 사용한다.
- 이름·이메일을 재입력받지 않는다. 서버가 확인한 `app_users.id`에 지급한다. 이메일이 없거나 가려진 카카오 계정도 신청할 수 있다.
- 계정 확인 → 대표 채널 등록 → 항목별 동의 → 지원 현황. 계정 변경 시 동의와 이전 계정의 초안을 초기화한다. 재로그인은 같은 계정의 채널 초안만 복원하며 동의는 다시 받는다.
- 이름·이메일은 서버에서 마스킹한다. 가입일은 `app_users.created_at`을 한국 시간으로 표시한다. 개인 응답·제공 이미지는 `private, no-store`다.
- 신청 중에는 안내 팝업 구성요소를 마운트하지 않는다. 안내 완료·확인 기록을 작성하지 않고 기존 안내 순서를 유지한다.
- 관리자: `/admin/easycutcutcutcutcutcut?tab=creator-support`.
- 실제 홈페이지 게시·SNS 발행·광고 집행·메일 발송은 자동으로 실행하지 않는다.

## 사용량과 중복 방지

프로그램 `creator_support_2026_v1`, 사용량 상품 `creator_support_30min_v1`, 동의 버전 `2026-09-11.v1`.

`enroll_creator_support`가 한 거래에서 신청·동의 원문·회차 연결·1,800초 지급분 3개를 생성한다. 최초 활성화 시각이 기준이며, 각 회차의 `valid_from`/`expires_at`으로 사용 여부를 판정한다. 별도 월별 지급 서버는 없다.

각 경계는 한국 시간 기준 원래 날짜·시각에 0·1·2·3개월을 더한다. 월말은 해당 월의 마지막 날로 보정하되 다음 달은 원래 기준일을 다시 사용한다. 예: 1월 31일 → 2월 말일 → 3월 31일. 홍보 종료는 최초 활성화 +12개월이다. 경계 시각은 시작 포함·만료 제외다.

프로그램/회원, 프로그램/정규화 채널 해시의 고유 제약, 계정 행 잠금, 요청 ID로 재시도·동시 신청을 처리한다. 지급 대상 ID는 요청 본문에서 받지 않는다. `accountKey`는 표시한 계정과 현재 세션이 같은지 비교하는 불투명한 확인값이며 지급 대상 선택에 사용하지 않는다.

채널 주소는 플랫폼·호스트·프로필 경로를 검증하고 추적 쿼리·프래그먼트·끝 슬래시를 제거한다. 인스타그램 사용자명과 유튜브 핸들의 대소문자를 통일한다. 유튜브 채널 ID의 대소문자는 유지한다. 서로 다른 별칭 URL이 같은 실제 채널인지 조회하는 기능은 포함하지 않는다. 실제 권리 검토 때 함께 확인한다.

무료 회원의 사용 가능 상품 목록, 잔액 표시, 생성 권한, 예약·차감 함수, 관리자 회원 잔액, 사용 내역에 상품을 연결했다. 유료 사용량 우선 차감과 유료 기능 권한을 유지한다. 예정 회차는 현재 잔액 및 지급 완료 내역에서 제외된다. 사용 내역의 지급일은 생성 시각이 아니라 회차 시작 시각이다.

## 운영과 개인정보

신규 모집은 데이터베이스 초기값 **OFF**다. 관리자에서 현재 버전의 실제 법률 검토 완료 기록을 등록한 뒤 모집을 열 수 있다. 운영사는 기존 방침과 같은 **아티룸**, 문의·철회 요청은 **easycut@easycut.co.kr**이다.

검토할 항목은 필수 참여 동의의 적법성, 개인정보 수집·이용과 공개·제공 구분, 수신자·이용 기간, Meta·Google 플랫폼 제공 및 국외 이전 요건, 1년 소재 이용약정, 별도 소재 사용료 없음, 법정 철회권과 처리 절차다. 구현된 문구는 검토 대상 초안이며 법률 검토를 완료한 것으로 간주하지 않는다. 문구가 바뀌면 버전과 데이터베이스 설정을 함께 갱신하고 모집을 닫아 재검토한다.

근거 확인: [개인정보 보호법 제37조·제38조](https://law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900078593). 개인정보 처리 동의 철회 등 법정 권리를 배제하는 문구는 넣지 않았다. 이메일을 회원 식별 기준으로 삼지 않는 설계는 [카카오 로그인 사용자 정보 안내](https://developers.kakao.com/docs/ko/kakaologin/common)에 따른 이메일 미제공·마스킹 가능성도 고려한다.

이미지는 선택 항목이다. 2MB 이하 JPG·PNG·WEBP 정지 이미지를 서버에서 최대 512px WEBP로 변환하고 메타데이터를 제거한다. 최대 256KB를 비공개 테이블에 저장한다. 미등록 시 이름·링크만 이용한다. 업로드는 로그인·계정 확인·모집 상태·계정별 개수 제한을 적용한다. 신청자 또는 관리자만 이미지를 읽을 수 있고 기간 종료·철회 후 이미지 응답을 차단한다.

권리 확인은 운영 권한·소재 권한 및 실제 매체별 제공 요건을 확인한 뒤 문서/고객센터 티켓 참조를 기록한다. `approved`이면서 기간 내이고 철회·탈퇴하지 않은 신청만 관리자 홍보 가능 목록에 포함된다. 이미지 크기·배치 조정 범위를 넘어서는 영상·썸네일·후기·얼굴·음성 활용은 추가 허락 대상이다.

철회·종료 처리는 공개 정보·이미지를 삭제하고 홍보 상태를 중단하며 미래 지급분을 취소한다. 이미 시작한 회차의 기존 만료일은 유지한다. 자동 위약금·환수는 없다. 외부 게시물·광고는 담당자가 실제로 중단하고 **게시·광고 중단 확인**을 기록해야 한다. 기간 종료도 같은 확인 대기 상태로 표시한다. 이 시스템이 외부 광고를 자동 중단했다고 간주하면 안 된다.

기존 결제 갱신 유지관리 호출에 자료 정리를 연결했다. 이 유지관리의 성공 여부와 무관하게 회차 활성화·만료 및 홍보 가능 목록의 기간 판정은 시각 조건으로 작동한다. 관리자에서도 정리를 실행할 수 있다.

- 미사용 업로드: 24시간이 지나면 정리.
- 채널 원문·이미지: 홍보 기간 종료 또는 철회·탈퇴 처리 시 삭제.
- 동의 상세·신청 처리 상세: 지원 종료 +1년 후 정리.
- 중복 확인용 회원·채널 해시·지급 연결: 프로그램 운영 중 유지. **모집 영구 종료** 후 지원 종료 +1년이 지난 신청부터 정리. 영구 종료는 다시 열 수 없으며 기존 지원 약속에 영향을 주지 않는다.
- 기존 회원 정보와 사용량 원장은 각각 기존 서비스·사용량 기록의 보관 정책을 따른다. 참조 문서/티켓에는 불필요한 개인정보를 복사하지 않는다.

## 데이터베이스 적용과 공개 순서

1. 현재 실제 운영 승격 커밋을 다시 확인하고 변경만 옮긴다. 이 작업은 2026-09-11 확인 당시 운영 배포 `dpl_7s3Zj8RDsTyFuwkK3LRw2XugeC9P`, 커밋 `54b4e34d7468a1678b8a7f3c913f321a37460ad4`에서 분리한 `codex/creator-support-20260911` 브랜치다.
2. lab 작업은 기존 lab 작업트리의 경계 확인과 준비 도구를 사용한다. `npm run lab:boundary`가 통과한 뒤에만 원격 변경한다. production SQL을 lab에 그대로 실행하지 않는다. lab은 `shorts_lab` 및 제한된 `shorts_lab_runtime` 접근 권한·RLS·함수 실행 권한으로 변환/검증해야 한다.
3. 적용 순서: `202609110004_creator_support.sql`, `202609110005_creator_support_usage.sql`. 일반 브라우저 역할에는 새 테이블·함수 권한을 주지 않는다. 서비스 서버만 사용한다. 첫 마이그레이션이 신청·기록을 만들고, 두 번째가 기존 예약 함수의 무료 상품 목록에 지원 상품을 추가한다.
4. 모집 OFF 상태로 인증 복귀·신청·지급·사용량·관리자 흐름을 lab에서 확인한다. 테스트용 모집과 실제 모집을 혼동하지 않는다. 예정 지급분을 현재 잔액에 더하지 않는다.
5. 실제 법률 검토 및 구글·카카오 OAuth 복귀, 모바일 실기기 키보드·글자 확대 확인 후 공개한다. 배포는 별칭 없는 후보 URL에서 주요 경로를 검증하고 동일 배포를 승격하는 기존 절차를 따른다.
6. 공개 후 관리자에서 법률 검토 기록을 등록하고 모집 ON. 기존 결제 유지관리 호출 실패 알림 및 홍보 중단 확인 대기 목록을 운영자가 확인한다.

마이그레이션 적용 전에도 페이지는 열리며 인증된 계정에는 모집 준비 상태를 표시한다. 기능 중단은 모집 OFF로 처리하고 기존 지급분·원장은 삭제하지 않는다. 약정된 지급이 남아 있을 때 사용량 상품 연결 코드를 되돌리지 않는다.
